# ADR-009: 映射 / 参数回退 / 模型降级 —— 三层切开，方向由成本决定，降级只允许能力驱动

## Background
调用方按目标契约写的是**具体 Seedance 模型 ID**（`doubao-seedance-2-0-260128` 等 7 个，
`seedance-api-reference.md` §7.1），而上游只有 **8 个粗槽位**。这个降维天然有损，
于是三个问题同时出现，且极易被当成一件事处理：

1. **映射**：名字 → 槽位。旧实现是脚本内**顺序敏感的正则**（`_MODEL_PATTERNS`），
   调换两行即静默错映射；且调用方无法预知"写这个名会打到哪"。
2. **参数回退**：取值不在允许集里怎么办。现行 `resolve_duration` 用"就近吸附、平局向下"，
   于是 `6s→5s`（对）与 `7s→8s`（**涨价 +60%**）的差别只是"谁更近"，**且回退后不回看 `max_credits`**。
3. **模型降级**：请求该模型接不住时能不能换一个。**当前完全没有机制**，而它是最危险的一环：
   换了模型身份 = 换了供应商，却可能只是一句 warning。

已知观测使得第 3 点的代价具体化：上游 `t2v` 槽位的实际产出**来自 minimax_h3**
（成品 URL 可见，`aivideomaker-api` 技能的计费实验），码率约 `seedance20` 的 1/4.8。
⇒ 便宜档**不是"Seedance 的便宜版本"，是另一个厂商的模型**。

## Decision

### D1. 三层必须切开，授权互不继承
L1 路由映射 / L2 参数回退 / L3 模型降级是三个独立授权面。
**"参数回退不了就换个模型"被明确禁止** —— 那等于让 L2 的失败触发 L3。

### D2. 参数回退的方向由**成本**决定，默认向下
新增两个正交开关（渠道级）：

| 开关 | 默认 | 语义 |
| --- | --- | --- |
| `fallback_direction` | **`down`** | 只落在不长于/不高于/不宽于请求的档位 |
| `fallback_policy` | **`adjust`** | 回退并如实上报；`strict` = 不回退直接 400 |

⇒ `6s→5s` ✅、`7s→5s` ✅（**不再是 8s**）、`21:9→16:9` ✅、`2s`（低于区间下界）⇒ **400**。
要 `7→8` 的调用方显式给 `fallback_direction: "nearest"`。

**理由**：向上回退是**静默涨价**，与 ADR-004 属同一类资金风险；向下回退只改变产品规格，
**永远不在账单上给惊喜**。宁可短，也不悄悄多花钱。

**附带的顺序要求**：回退必须在**上限判断之前**完成，并在**回退后的取值**上重新估算 ——
否则 `7→8` 超上限时，调用方收到的 400 会指向 `duration`，而真实原因是"适配层替你升了一档"。

### D3. 连续区间维持钳制；区间也要受方向约束
`minimax` 5–20 / `seedance20` 4–15 / `happyhorse` 3–15 **不做吸附**（v1 已对）。
但"钳制向上"同样涨价 ⇒ `down` 模式下低于下界 **400**，不得自动抬到 `min`。
`duration: -1`（目标契约支持、上游全不支持）必须替换为具体整数并上报。

### D4. `ratio: adaptive` 不再默认落 `16:9`
有首帧 ⇒ 从图片实际尺寸反推；上游支持自选（`minimax` 的 `auto`）⇒ 原样映射；
两者都不满足 ⇒ **400**。理由：竖屏素材上 `adaptive` 与 `16:9` 是**两个不同的产品**，
落 `16:9` 是替调用方猜。

### D5. 模型降级只允许「能力驱动」，五种情形禁止降级
只允许在"换模型**不改变用户想要什么**"（playbook §3.2 判据）时降级。
**禁止触发**：① 上游 5xx/429/超时/连不上（那是**可用性**，答案是重试/退避，不是换供应商）；
② 超出 `max_credits`（不许改产品来迁就预算）；③ 请求含参考类素材而目标接不住（400）；
④ 目标能力**更弱**；⑤ 目标是**另一个 provider**。
降级目标必须**能力 ⊇ 需求**，且 **估算不得高于原模型**（"降级"变"升级" ⇒ 400）。

### D6. 映射改为渠道声明的表，未命中/歧义一律 400
`X-Channel-Options.model_map`：精确键优先、通配键按最长匹配；
**未命中 ⇒ 400 + 可用名**，**歧义 ⇒ 400 + 候选**（歧义不猜：`2.0` 与 `2.0 fast` 代价差数倍）；
命中哪条规则要进上报（`model.map.hit`）。映射表不得跨 provider（ADR-002）。

### D7.（**2026-09-16 取代**）降级告知的出口是 logfire 与 `dry_run`，**不是响应体**

原决定"新增结构化上报块 `degradations[]`"**未实现，且位置已作废**：`ADR-011` 把响应体收敛为
**原生字段** ⇒ 里面既不会有 `degradations[]`，也不会有 `warnings[]` / `effective` / `unsupported[]`。

但**降级的告知义务没有取消**，只是换了出口：

| 出口 | 内容 |
| --- | --- |
| logfire `task.snapshot` | `task.warnings[]`（人类可读）+ `task.unsupported[]` + `task.effective.*`（`upstream_model` / `model_requested` / `model_map_applied` / `estimated_credits`）+ `task.usage.*` |
| `X-Dry-Run: 1` | `requested` / `effective` / `warnings[]` / `unsupported[]`（**形态不变**，`ADR-010` D5） |
| 描述产物的字段 | `duration` / `resolution` / `ratio` / `generate_audio` / `draft` / `seed` 按**实际生效值**回显 |

结构化 `degradations[]`（`kind` 枚举 + `credits_delta` + `vendor_changed`）的设计**保留在
`docs/04` §4 作为草案**，但"要做就放在 `effective` 块与 logfire 属性里"——那是机器可读差值的既有落点。

⚠️ **已接受的代价**：响应体不再能一眼看出"我被降级了"。接入方必须主动用三个通道之一
（生效值字段 / `dry-run` / logfire）。这是本次契约收敛的直接代价，记在 `ADR-011`。

### D8. 已有决定不改（**上报形态按 D7 修正**）
尾帧在单图上游上**可丢**（playbook §3.1 的原决定保留），但必须**如实上报** —— 它决定的是
**结束画面**。⚠️ 原措辞要求"结构化上报为 `capability_dropped`"，**该结构化块未实现**；
现状是 `warnings[]` 里一条人类可读的说明（"has no last-frame input; the last frame was dropped"）
→ 进 logfire。若将来做结构化（待定项），这一条与 D7 一并落位。

## Consequences
- **正面**：把"会不会涨价""是不是换了供应商"从**字符串警告**变成**可编程事实**，
  调用方能据此决定重发/加预算/改需求；这正是"降级报告承担语义判断"（ADR-005）要的形态。
- **正面**：默认 `down` 让"参数取整"这件事**不可能产生意外账单**，与 ADR-004 形成闭环。
- **正面**：映射表外置后，同一份脚本可服务多个上游；新增上游不再改脚本（改配置）。
- **负面**：默认 `down` 会让部分调用方拿到比预期短的片子（`7s` → `5s`）。这是**刻意**的
  取舍 —— 账单惊喜比时长惊喜贵得多。需要产品侧确认（OPEN-DECISIONS）。
- **负面**：（2026-09-16 更新）响应体已收敛为原生字段（`ADR-011`）⇒ **降级告知不再出现在响应体**。
  调用方若既不读 `dry-run`、也不看 logfire，就**无法感知**自己是否被降级 —— 这是既定取舍。
- **负面**：`degradations[]` 未实现，且**不会**作为响应字段实现（原计划作废）。要结构化时落点是
  `effective` 块 + logfire 属性。
- **负面**：`model_map` / `fallback_chain` 挂在请求头上会让头变长，链一长可能吃紧；
  是否改为部署级配置待实测（OPEN-DECISIONS）。
- **风险**：`vendor_changed` 依赖"映射表知道每个槽位背后是谁"。上游不保证槽位实现不变
  ⇒ 该字段**只能标注"按当前已知"**，不得被当作计费或合规依据。
