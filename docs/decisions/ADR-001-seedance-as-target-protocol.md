# ADR-001: 目标协议选火山方舟 Seedance 原生异步任务协议

## Status
Accepted (2026-09-13)

## Background
需要一层适配，把**任意视频生成上游**接进来，让调用方"只改 Base URL 与 Key"。
可选路线有两类：(a) 自己设计一套统一接口；(b) 选一份已经成熟的厂商协议作为目标契约。

Video 生成的能力面很宽：文生 / 图生（首帧、首尾帧）/ 视频生 / 全能参考（图+视频+音频）/
音画联合 / 编辑 / 延长 / 样片 / 尾帧拼接。自己设计接口等于要把这些语义重新定义一遍，
且调用方仍要学一套新东西。

## Decision
以**火山方舟 Seedance 原生协议**为目标契约（`docs/seedance-api-reference.md` 为唯一真源），
逐字实现其 4 个端点与字段体系。

理由：Seedance 是**规范化的超集协议** —— 上述全部能力收敛在同一组端点 + 同一套字段体系下
（`content[]` 多模态数组 + 顶层生成参数）。上游普遍是它的**子集**。

## Consequences
- **正面**：适配工作的主干变成**降维投影 + 显式降级报告**，不需要设计接口；
  调用方迁移成本 = 换 Base URL + Key；已有 SDK / 正则 / 日志关联全部沿用。
- **正面**：任务 ID 形状可以模仿原厂（`cgt-YYYYMMDDHHMMSS-xxxxx`），调用方无感。
- **负面**：必须处理"超集 → 子集"的降级，且**降级不能静默** —— 参考类素材
  （`reference_image` / `video_url` / `audio_url`）丢不掉，丢掉就得 400。
- **负面**：`content[]` 的 `role` 位置等细节以官方为准，第三方兼容网关的文档
  **会与原厂 divergent**（实测：把 `role` 写进 `image_url` 对象内），不能当实现依据。
