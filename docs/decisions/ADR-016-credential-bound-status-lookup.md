# ADR-016: 上游查询接口**没有参数**时，任务身份来自凭证 ⇒ 必须验明记录归属

## Status
Accepted (2026-09-17)

## Background

`senseaudio` 的官方文档把查询写成 `GET /v1/video/status?id=<task_id>`，并把 `id` 标为**必填**。
用户实测（2026-09-17 提供的 curl）给出的实际形态是：

```bash
curl -X GET "https://api.senseaudio.cn/v1/video/status" \
     -H "Authorization: <token>"
```

**没有任何查询参数**：身份只能来自**凭证**（API key）。这条差异带来一个此前所有上游都没有的
新问题：**我们要问的任务，和上游回答的任务，可能不是同一个**。

最坏形态（会在完全没有征兆的情况下发生）：

> 同一把钥匙先建了 #A；#A 在上游跑完，但**没人轮询过它**（本地仍非终态）。
> 随后同一把钥匙建了 #B ⇒ 上游的"当前任务"变成 #B。
> 这时查 #A，上游回的是 **#B 的记录**。若直接采信：
> #A 会被标成 `succeeded`，并且 `content.video_url` 给的是 **#B 的产物**。
> 产物链接**真的能下载**、状态也是**真的** —— 只是属于另一个任务。
> 而在 `ADR-011` 之后，诊断信息已经不在响应体里，调用方**没有任何办法看出来**。

⚠️ 既有的凭证绑定（`ADR-003`）**不覆盖**这件事：它保证的是"不是你建的，就别让**你**查到"
（本地 404，不发上游）；这里的问题相反 —— 钥匙是对的，只是上游**答非所问**。

## Decision

`senseaudio/video@v1` 增加渠道选项 `status_binding`，**默认 `credential`**：

| 值 | 请求 | 谁保证"这是本任务" |
| --- | --- | --- |
| `credential`（默认） | `GET /v1/video/status`（裸 URL，不带参数） | **我们**：`query_response` 比对返回记录里的 `task_id` 与本任务的 `upstream_task_id` |
| `task_id` | `GET /v1/video/status?<query_id_param>=<task_id>`（官方文档形态） | 上游按参数过滤，**我们不做校验** |

三条必须同时成立：

1. **不匹配就拒绝**：400 `InvalidParameter`（`param=id`），消息里点名"它回的是哪个任务、
   我要是哪个任务"，并给出下一步（把任务轮询到终态再建下一个；配 `max_concurrency=1`）。
   **绝不采信** —— 采信就是上面那段"看起来一切正常"的静默错。
2. **不过度拒绝**：`task_id` 绑定形态放行（上游自己过滤）；返回体不是对象放行；
   **记录里没有 `task_id` 字段也放行**（无据可依，不能凭空拒绝 —— 否则上游一改字段，
   我们就从"答非所问"变成"谁都查不动"）。
3. **连带建议 `max_concurrency: 1`**：上游一次只认得一个任务。本层替上游兜不住这件事，
   但渠道能 —— 而引擎的并发闸门键恰好是 `provider:凭证指纹`，与上游的语义**同一根轴**。

## Consequences

- **正面**：堵住了"把别的任务的状态与产物写到本任务上"这一类静默错。
  它是本项目目前**唯一**一处"拿到 2xx 也必须拒绝"的地方，理由记在脚本决定 9 与这里。
- **正面**：两条形态都在，且形态本身是**渠道声明**（`status_binding`）——
  实测发现该接口要带参数时改一行配置，不用发版。
- **负面 / 已接受**：被顶掉的旧任务从此**查不到状态**（上游事实），本地只能返回 400
  并说明原因。它的并发槽位会一直占着，直到引擎看门狗按 `execution_expires_after` 置 `expired`
  （默认 172800s）。**不接受**的替代方案是"返回上一次的状态 / 返回 `running` 并告警" ——
  那会让调用方**永远等一个不会到来的终态**，而且看起来一切正常。
- **负面 / 已接受**：这条约束**只有配了 `max_concurrency: 1` 才真正无感**。
  若运营方把并发放到 2 以上，同一把钥匙就会出现"新任务顶掉旧任务"，旧任务的查询会开始 400。
  这不是本层的缺陷，但**必须在接入文档里说清楚**（已写进上游契约 §2.2 与 README）。
