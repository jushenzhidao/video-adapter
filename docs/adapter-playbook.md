# 「任意上游 → 火山 Seedance 协议」适配方法论

> **适用场景**：把任意第三方视频生成能力（自建模型、厂商云 API、网页端内部接口、聚合网关）
> 包装成火山方舟 Seedance 原生的异步任务协议，使调用方**只换 Base URL 和 Key** 即可接入。
>
> **核心判断**：Seedance 是**超集协议**（见 `seedance-api-reference.md` §0.1），上游是**子集**。
> 所以适配层的主干工作是**降维投影 + 显式降级报告**，而不是设计接口。

---

## 1. 前门契约（不可协商的部分）

前门必须逐字实现 `seedance-api-reference.md` 的四个端点：

```
POST   /api/v3/contents/generations/tasks          → {"id": "cgt-..."}   （只回 id！）
GET    /api/v3/contents/generations/tasks/{id}     → 完整任务对象
GET    /api/v3/contents/generations/tasks          → {items:[...], total}
DELETE /api/v3/contents/generations/tasks/{id}     → 取消（仅 queued）/ 删除
```

三个前门细节：
1. **路径逐字等于原生**：`/api/v3/contents/generations/*`，不加前缀也不加路径段。
   不做 LAS `/api/v1` 与 Agent Plan `/api/plan/v3` 的前缀兼容（同一逻辑 API 的另两种投放形态，
   非接入目标）；多前缀若真需要，属**部署层反代**职责。
2. **多上游靠 `model = provider/model` 区分**：一个 `base_url` 服务所有上游，如
   `"model": "aliyun-bailian/deepseek-v3"`。
   🔴 **`provider` = API 供给方，不是模型出品方**：同一个 `deepseek-v3` 由
   `deepseek-official` / `aliyun-bailian` / `volcengine-ark` 提供时是三套端点与凭证，
   **不能写成 `deepseek/...`**（否则三家撞成一个 token → 误路由）。
   `provider` 必须与渠道声明一致，**不一致 → 400** —— 这条专门杜绝"模型名写错 →
   静默落到别的上游 → **直接付费**"。裸模型名走渠道默认 provider；渠道未声明就 400，不猜。
   任务键含 `provider`，**跨 provider 读任务必须 404**。
   ⚠️ `GET`/`DELETE` 路径与体里**没有 `model`** ⇒ 渠道身份只能来自任务记录（provider）
   ＋ 请求头（上游地址与凭证），两者不一致必须 404。
3. **任务 ID 形状要模仿原厂** `cgt-YYYYMMDDHHMMSS-xxxxx`，便于调用方沿用正则校验、日志关联不变。

## 2. 第一步：把上游归类（决定架构，先做这个）

拿到上游后**先判形态**，再写代码。三类形态的适配成本差一个数量级：

| 形态 | 特征 | 适配动作 | 成本 |
| --- | --- | --- | --- |
| **A. 原生任务式** | `POST create` 返回 task_id，`GET` 轮询状态 | 字段改名 + 状态/错误映射 | 低 |
| **B. 同步阻塞式** | 一次请求阻塞到出结果（或直接返回 URL） | **必须合成任务**：后台 worker 投递 + 本地 store + 伪造 `cgt-` id，`GET` 从 store 读 | 中 |
| **C. 长连接/流式式** | WebSocket / SSE 推送进度与分片 | 适配层维持长连接，把事件落 store，再对外呈现六态 | 中高 |

**形态 B / C 的关键约束**：一旦需要"合成任务"，适配层就必须自己承担**任务持久化**——
至少保留到 `GET` 任务的 7 天窗口（与官方对齐），且进程重启不能丢（落库或落盘，不能只放内存 dict）。
上游若比 7 天更早清理产物，**必须在终态时立即转存**。

## 3. 降级投影：`content[]` 的逐项映射规则

这是整个适配层最核心、也最容易做错的部分。

### 3.1 映射矩阵

| Seedance 输入项 | 上游常见对应 | 上游缺失时 |
| --- | --- | --- |
| `{text}` | `prompt` / `text` / `content` | 必填，缺失 → 400 |
| `{image_url, role:first_frame}` | 首帧图参数 `image` / `first_frame_image` / `image_urls[0]` | 上游是纯 t2v → **400**（模式不支持），不要悄悄退化成文生视频 |
| `{image_url, role:last_frame}` | `last_frame_image` / `tail_image` | 上游只支持单图 → **取首帧、丢尾帧 + warning**；上游完全无图能力 → 400 |
| `{image_url, role:reference_image}` | 主体/角色参考 `subject_reference` / `reference_images` | **400**（丢参考会让"同一个人"变成随机人，语义已变） |
| `{video_url, role:reference_video}` | v2v / 风格运镜参考 | **400**（能力不存在） |
| `{audio_url, role:reference_audio}` | 音频驱动 / BGM 参考 | **400**（能力不存在） |
| `{draft_task: {id}}` | 通常无对应 | **400** 并说明"上游不支持样片流程" |

### 3.2 判定准则（代替逐个字段拍脑袋）

> **丢掉这一项，会不会改变"用户想要什么"？**
> - **会** → 返回 `400`（`InvalidParameter`），并在 message 里指明是哪一个 `content[i]`。
> - **不会，只是画质/风格层面的弱化** → 保留、降级、写入 `warnings[]`。

按此准则，`reference_image` / `video_url` / `audio_url` / `last_frame` 的差别就自明了：
**参考类素材一律不能静默丢**（它们承担"控制"，不是"装饰"）；只有尾帧在单图上游上可降。

### 3.3 多项合并与顺序

- **多个 `text` 项** → 按数组顺序用换行拼接为单条 prompt（不要取最后一条）。
- **`@图像1` / `@视频1` 引用语法**：官方提示词里这是**位置引用**（第 n 个媒体项）。
  若上游要求显式编号参数，必须在**重排/裁剪 media 数组后同步重写提示词里的编号**，
  否则"参考@视频2"会指向错素材 —— 这类 bug 表现是"生成的视频参考了错误的东西"，极难归因。
- **首尾帧的无 role 隐式语义**：传 2 张无 `role` 的图 + 有文本 ⇒ 按顺序 = 首帧、尾帧。
  前门要显式归一化成带 `role` 的形式再往下走，避免这个隐式规则在上游侧失效。

## 4. 顶层参数的降维

| Seedance 字段 | 降维策略 | 风险 |
| --- | --- | --- |
| `resolution` | 上游档位映射；不支持 → 就近吸附 + warning | ⚠️ 就近可能**跨进更贵档**（见 §8） |
| `ratio` | 直传 `W:H`；上游只有枚举 → 吸附到最近比例 | `adaptive` 上游若无 → **由首帧图实际尺寸反推**，而非默认 `16:9` |
| `duration` | 钳制到合法区间 | ⚠️ 钳制向上会跨进计费档；`-1`（模型自选）在上游未支持时须替换为具体值 |
| `frames` | 优先于 `duration`；上游只认秒 ⇒ 按上游帧率换算并记账 | 换算不整时要回写**实际** duration |
| `seed` | `-1` 上游必填时 → 生成随机值并**回写到查询响应** | 回写不一致会导致"同 seed 复现不出来" |
| `watermark` | 上游不支持去水印 → 如实 warning（不要假装支持） | 商业场景敏感，必须进 `unsupported[]` |
| `camera_fixed` | 上游无对应 → `unsupported[]` | 参考图场景本来就不支持，可直接忽略 |
| `generate_audio` | 上游无声 → 若请求 `true` 则 warning；若上游强制有声而请求 `false` → **400** | 默认值随模型版本不同（1.x `false` / 2.x `true`），不要写死 |
| `return_last_frame` | 上游不返回尾帧 → 若调用方依赖它做拼接，**warning 要明确说"拼接链路会断"** | — |
| `service_tier` | `flex` 离线推理多数上游没有 → 降级为在线 + warning | 语义是"更慢更便宜"，静默降级等于悄悄涨价 |
| `draft` | 上游无样片 → 400 或忽略 + warning | 调用方靠它省钱，静默忽略会让其以为省了钱 |
| `execution_expires_after` | 上游无超时控制 → 适配层自己起看门狗，到点置 `expired` | 否则任务永久卡 `running` |
| `callback_url` | 见 §6 | — |
| `priority` / `safety_identifier` / `tools` | 上游无对应 → `unsupported[]` | 合规类字段建议**不要静默丢**（如实上报） |

### 4.1 弱校验后缀必须先剥掉

调用方可能用官方的**弱校验模式**把参数内联在提示词尾部：

```
"小猫打哈欠 --rs 720p --rt 16:9 --dur 5 --seed 11 --cf false --wm true"
```

适配层入口必须**先解析并剥离**这组后缀（`--rs/--rt/--dur/--seed/--cf/--wm`，以及全称形式
`--resolution/--ratio/--duration/--camerafixed/--watermark`），合并进结构化字段，
**再**把干净文本送上游。否则上游收到一段带 `--rs 720p` 的污染提示词，画面里可能真的出现文字。
解析优先级：**显式结构化字段 > 内联后缀**（与官方"常规方式优先"一致）。

## 5. 输出侧：产物与字段回填

| Seedance 输出字段 | 适配要点 |
| --- | --- |
| `content.video_url` | 上游产物 URL 常**需鉴权 / 短有效期** ⇒ 必须转存到自有存储，对外给稳定地址。不要直接透传上游预签名地址 |
| `content.last_frame_url` | 请求了 `return_last_frame` 但上游不给 → 适配层可自行抽帧生成（可选增强），或返回 `null` + warning |
| `content.file_url` | 非 mp4 容器时填这里，`video_url` 留给 mp4 |
| `resolution` / `ratio` / `duration` / `frames` | **回填上游实际产出值**，不是请求值 |
| `framespersecond` | 注意官方响应里 `framespersecond` 与 `framesPerSecond` 两种拼写都出现过，解析要容错 |
| `created_at` / `updated_at` | **epoch 秒**，不是 ISO 字符串 |
| `usage.completion_tokens` / `total_tokens` | 上游按秒计费时（大多数第三方）这里可给 0 或按 token 折算；但**不要伪造**，宁可省略并给 `billing.model` 说明 |
| `seed` | 回填本次实际使用的种子（见 §4） |
| `error` | 成功必须显式 `null`，失败给 `{code, message}` |
| 任务记录 | 与官方对齐**保留 7 天**；上游保留期更短则本地必须转存 |

## 6. 回调：形状转换 + 语义对齐

`callback_url` 是**适配层必须自己实现**的能力（它不是上游的字段，而是 Seedance 的契约）：

1. 适配层收到调用方的 `callback_url` 后**自己留存**，不透传给上游
   （除非上游回调体恰好同构——概率极低）。
2. 适配层从上游获得状态变化（轮询 / 上游回调 / 长连接事件），
   **转换成 Seedance 查询接口的响应体形状**，再 `POST` 给调用方。
3. 对齐可靠性语义：**5 秒内未收到成功确认则重试，最多 3 次**。
4. 调用方按 `id + status` 幂等；**主动 `DELETE` 成功后不触发回调**。
5. 推送状态集合 = `queued / running / succeeded / failed / expired`（**不含 `cancelled`**）。

> 若上游是形态 A（有原生 task_id）且提供回调，最优实现是"上游回调 → 适配层轮询确认 → 推送"，
> 而不是纯转发：上游回调体往往缺少产物 URL（需要再查一次），直接转发会让调用方拿到半成品。

## 7. 并发、幂等与容量

| 议题 | 做法 |
| --- | --- |
| 并发闸门 | 上游普遍限制同时在跑的任务数。**槽位从创建占到终态**，不是创建返回就释放（见既有经验：直连转发在第 N+1 个请求开始报错） |
| 排队而非失败 | 超出配额进等待队列，空槽自动 pump；日志显式打印 `UPSTREAM FULL (attempt i/n)` |
| 幂等 | 上游无 `Idempotency-Key` 时，适配层可按"请求指纹 + 时间窗"去重，避免调用方重试导致重复计费 |
| 429 分流 | 先看上游错误语义区分**配额限流**（退避有效）与**突发保护**（退避有效、扩容无效），再决定重试策略 |
| 超时看门狗 | 用 `execution_expires_after` 自己兜底置 `expired`，不依赖上游 |
| 可观测 | `GET /healthz` + `GET /queue` 暴露队列深度与闸门占用 |

## 8. 计费护栏（会真花钱的三处）

1. **默认档位要保守**：模型名映射到上游档位时**默认选便宜档**，高价档必须调用方显式要求。
   （既有教训：把听起来"高配"的模型名映射到高价档 ⇒ 任何人一调用就自动付费。）
2. **就近吸附可能跨档**：`duration: 8` 被吸附到 `10` 可能跨进计费区。
   提供 `prefer_free` / `prefer_cheap` 类开关，优先落在便宜区，并在 `warnings` 里**明确提示跨档**。
3. **`dry_run` 必须是一等公民**：用协议无关的请求头开开关（如 `X-Avm-Dry-Run: 1`），
   跑完**完整翻译 + 素材转存**后直接返回将要发出的 payload，**不提交上游**。
   这是把"验证翻译层"与"花钱"解耦的唯一手段。

> 铁律：**"适配 / 封装 / 写插件"类需求只做翻译层校验，不发真实生成请求。**
> 翻译层对不对，单测 + dry_run 就能证明；"上游能不能出片"不该由适配层替调用方花钱证明。
> 真要端到端实跑，只用最便宜档位，且**发之前先问**。

## 9. 测试清单（零消耗）

| # | 用例 | 断言 |
| --- | --- | --- |
| 1 | 文生视频最小请求 | 上游收到的 body 正确，`dry_run` 下无网络调用 |
| 2 | 5 种 `content[]` 组合 | 投影结果符合 §3.1 矩阵 |
| 3 | 上游缺失能力（如 v2v） | 返回 **400** 而非静默降级 |
| 4 | 上游仅单图 + 首尾帧请求 | 取首帧、尾帧进 `warnings` |
| 5 | `role` 放在两种位置（顶层 / 对象内） | 都能正确解析，出口一律顶层 |
| 6 | 弱校验后缀 | 后缀被剥离，prompt 干净，参数生效 |
| 7 | 状态映射 | 上游 6+ 种状态名各映射到 Seedance 六态之一 |
| 8 | 错误映射 | 上游错误 → 正确 HTTP + `error.code`（400/401/403/404/429/500） |
| 9 | 并发闸门 | 5 个并发提交峰值 ≤ N；超限排队而非失败；终态释放 |
| 10 | 回调 | 形状 = 查询响应体；5s 无确认重试 3 次；`cancelled` 不推送 |
| 11 | 幂等 | 重复提交不产生第二个上游任务 |
| 12 | 计费护栏 | 无显式上限 + 官方线 → 400 且**无网络调用**（用死端口验证） |
| 13 | 任务持久化 | 进程重启后 `GET` 仍能取到任务（形态 B/C 必测） |
| 14 | 素材转存 | 上游返回需鉴权 URL → 对外 URL 可直接下载 |

**测试输入一律用 data URI 或本地 fixture**，不要用虚构外链：适配层会真去下载，
`502 upstream_unreachable` 会把真正想验证的错误映射盖掉。

## 10. 分层与交付物

```
app.py            # FastAPI 路由：四个端点 + 错误信封 + /healthz + /queue
translate.py      # 纯函数：Seedance 请求 ⇄ 上游请求（env 显式注入，不读 os.environ）
store.py          # 任务持久化（形态 B/C 必需；保留 ≥7 天）
client.py         # 上游客户端（含 trust_env 开关）
queue.py          # 并发闸门 + 延迟执行 + 退避
media.py          # 素材入站转存 + 产物出站转存（magic bytes 嗅探，不信扩展名）
callback.py       # 回调形状转换 + 重试 3 次
observability.py  # 日志/追踪，未配置时必须静默降级为 no-op
tests/            # §9 的 14 个用例，全部零消耗
```

> 纯函数层（`translate.py`）是价值密度最高的地方，测试主要压这里；
> 它必须能做到 `importlib` 直接加载、用假 ctx 跑一遍，不需要起服务、不需要网络。

## 11. 复用经验：如何快速吃下一个厂商的视频协议

本次实测有效的路径（按性价比排序）：

1. **别抓控制台文档页**。`console.<cloud>.com/.../docs/<id>` 是 JS 渲染，只能拿到标题。
2. **换 `docs.` 子域**。同一文档 ID 在 `docs.volcengine.com` 上多数能拿到完整字段表 + 官方 SDK 示例 + 响应示例。
   仍有部分页面是空壳（只回标题与目录链接）—— 别在这上面死磕。
3. **联网检索是最有效的补缺口手段**。搜索引擎返回的页面正文片段**经常直接包含完整参数表**，
   用字段名关键词（如 `role reference_image duration`）去搜，比反复抓页面快得多。
4. **第三方兼容网关文档当"反向参考实现"读**。同一份逻辑 API 常被多家网关原样代理
   （网易云信 / 融云 / 302.AI / reAPI / CrazyRouter），它们的文档里字段表齐全、还有状态枚举的"实现态"命名，
   可用来确认字段名与语义。⚠️ 但**它们会与原厂产生 divergent 写法**（本次实测：`role` 被写进 `image_url` 内部，
   官方是 content 项顶层）⇒ **实现依据只能是官方文档或官方 SDK 示例**，镜像仅用于交叉验证。
5. **响应示例比字段表更值钱**：照着它写 `normalize_task`，字段名、时间单位（epoch 秒 vs ISO）、
   默认值（`generate_audio` 1.x `false` / 2.x `true`）一次对齐，不用猜。
6. **找官方 SDK 的调用示例**：它是唯一能证明"字段放在哪一层"的硬证据。
   本次正是官方 Python SDK 示例钉死了 `role` 的位置。

**产出物**：本仓库的 `docs/seedance-api-reference.md` 就是这条路径的产物 —— 下次接新厂商时，
把它当"目标契约"，只需要重复 §2–§4 的上游归类与投影设计。
